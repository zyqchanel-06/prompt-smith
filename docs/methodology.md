# 六槽位方法论：为什么是这六个

> 这是本框架的"世界观"。不理解这一层，档案只会写成一堆词库。

## 一句话

**把"我想要一张什么图"拆成六个互相独立的维度**，每个维度只管一件事。这样：
- 换场景不用重写人物
- 别人的档案能直接套用到你的需求
- 出问题时可以二分定位（是人物崩了，还是场景词打架）

## 六个槽位

| 槽位 | 管什么 | 典型内容 | 不要放什么 |
| --- | --- | --- | --- |
| `subject` 人物 | 谁、几个人、身材特征 | `1girl, solo, long hair, slim` | 表情、服装、背景 |
| `outfit` 穿搭 | 穿什么 | `black evening dress, long gloves` | 姿势、场景 |
| `scene` 场景 | 在哪 | `ballroom, chandelier, red carpet` | 光线方向（放 expression/氛围里更好） |
| `pose` 姿势动作 | 身体怎么摆 | `standing, looking at viewer, hands on hips` | 构图（全身还是半身） |
| `expression` 表情氛围 | 情绪、光线、气氛 | `soft smile, blush, candlelight, ethereal` | 画风、质量词 |
| `framing` 构图 | 画面取景范围 | `full body`, `upper body`, `close-up` | 镜头型号（那是另一个体系） |

## 为什么槽位之间要"互斥"

槽位的价值在于**正交**。如果一个 tag 同时属于两个槽位，就会出现：

- 档案里 `scene` 默认写了 `dim lighting`，用户在 `expression` 里又写了 `bright`
- 两个槽位都拼进正向提示词 → 光线词打架 → 画面发灰

所以规则：**一个概念只放一个槽位**。光线、氛围归 `expression`；场景只描述"在哪"。

## 为什么顺序是这个顺序

`subject → outfit → scene → pose → expression → framing`

这不是审美偏好，而是**语义粒度从大到小**：

1. 先确定"谁"（主体，权重最高）
2. 再确定"穿什么"（附着在主体上）
3. 后确定"在哪"（背景）
4. 姿势属于主体动作，紧跟主体
5. 表情氛围是修饰层
6. 构图是全局约束，放最后

同类信息聚在一起，CLIP 的注意力更容易把它们关联起来。反过来把 `full body` 写在 `1girl` 前面，模型更容易画成半身——构图词被更靠前的语义带偏了。

## 槽位默认值：什么该做默认

档案里每个槽位可以给 `default`。判断标准：

| 该做默认 | 不该做默认 |
| --- | --- |
| 你几乎每次都想要的东西（如 `full body`） | 只是这次想用的东西 |
| 缺失时会导致出图崩掉的东西（如 `solo`） | 可选装饰 |
| 能让提示词"填满即可用"的东西 | 需要具体判断的东西 |

默认值的作用是**降低每次的输入成本**。一次 `build` 只需要填 1~2 个槽位，其余交给档案——这正是"口味档案"能复用的原因。

## 反例：什么不该做成槽位

- **质量词**（`masterpiece`）→ 它们每次都一样，属于档案的 `quality` 字段，不是槽位
- **负向提示词**（`lowres`）→ 属于 `negative_base`
- **触发词**（`anime style`）→ 属于 `trigger`，永远第一位
- **画风** → 触发词 + LoRA 决定，不该在槽位里重复

槽位只放"每次会变"的东西。

## 和 LLM 的分工

这套槽位设计的一个副产品：**它天然适合让 LLM 去填**。

- LLM 负责"听懂人话 → 填六个字段"（模糊、需要理解）
- 本框架负责"填好的字段 → 稳定提示词"（精确、需要可复现）

把不确定性挡在边界外，是这套设计能写单测、能定位问题的根本原因。
