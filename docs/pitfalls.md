# 实战踩过的坑

这些不是理论，是实际跑坏过的画面换来的经验。

## 1. 环境调亮 ≠ 人物肤色白

**最贵的一课。**

想让角色皮肤白，直觉是往正向堆 `bright theme`、`high key lighting`、`white background`。结果：

```
亮度 233 / 对比度 19  → 废稿
```

整个画面被推白了，皮肤反而不突出，细节全糊。

**正确做法**：白的是**皮肤**，环境保持原本的调性。

```
✅ (pale skin:1.25), fair skin, porcelain skin
❌ white theme, high key, bright interior
```

这条经验在 `forbidden` 里应该被写成红线——本框架的示例档案就是这么做的。

## 2. 只加正向词，不改负向

把 `tan skin, dark skin` 放进负向，配合正向的 `pale skin`，效果远好于在正向里堆十个"白"的同义词。

**负向提示词是减法，正向是加法。** 想"少出现什么"，用减法。

## 3. 两个光源同时出现

`daylight` + `candlelight`、`sunset` + `moonlight`——模型不会"选一个"，它会画一个发灰的中间态。

这就是 `conflicts` 规则存在的意义：**互斥概念必须显式声明**，让它 warn 你。

## 4. 权重越加越多

`(tag:1.5)` 一次两次还行，堆多了会出现：

- 局部过饱和、颜色怪
- 元素形态崩坏（尤其手、脸）
- 整体失衡（某一部分太抢眼）

经验：**单次不超过 2~3 个加权项，范围 0.8~1.3**。

## 5. 视觉模型不可靠

多模态接口常见问题：超时、返回"看不清"、描述和实际不符。

**不要把流程卡在视觉模型上。** 用数字门（亮度/对比度）做初筛，判断"是不是我要的"交给人的眼睛。这是本框架把 `quality` 做成可选依赖的原因——它不该成为关键路径上的单点。

## 6. 显存竞争

SDXL 出图 + LoRA 训练同时跑，8GB 卡必炸。表现是 ComfyUI 卡死或者 OOM 退出。

**规则：训练期间不出图，出图期间不训练。**

## 7. 文件名不带主题

三个月后回头看 `00042_.png`，完全不知道当时在试什么。

**命名规范**：`<风格前缀>_<主题>_<序号>.png`，例如 `anime_ballroom_01.png`。种子、参数一起记进 CSV 更好。

## 8. 提示词顺序被忽略

把 `full body` 写在 `1girl` 前面，出图半身率明显上升。构图词越靠前，越容易被当成"主体的一部分"来理解。

**顺序不是审美，是语义结构。** 详见 [prompt-anatomy.md](prompt-anatomy.md)。

## 9. 档案写成了词库

档案里塞了 200 个 tag，结果每次 `build` 出来的提示词都超长、互相打架。

**档案是"默认值 + 约束"，不是"词库全收"。** `slots.*.tags` 只是候选提示（给人看的），真正进提示词的是 `default` 和用户当场填的槽位。
