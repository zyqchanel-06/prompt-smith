# 量化质量门：用数字判断画面有没有跑偏

## 为什么需要它

出图之后，"这张行不行"通常靠肉眼。但有两个场景肉眼不可靠：

1. **批量出图**（一次 10 张，人眼会疲劳，标准会漂移）
2. **视觉模型不可用**（多模态接口超时、限流、连不上）

而"画面过曝"和"对比度发灰"这两个最常见的失败，其实可以用**两个统计量**粗略识别，成本几乎为零。

## 两个指标

```
brightness = 灰度图的平均像素值        （0~255）
contrast   = 灰度图的标准差            （0~128）
```

- **亮度**：整体偏亮还是偏暗。正常人物立绘大概在 110~175
- **对比度**：画面的明暗起伏。太低 = 发灰发闷；太高 = 死黑死白

## 典型失败画像

| 现象 | 亮度 | 对比度 | 说明 |
| --- | --- | --- | --- |
| 正常 | 110~175 | ≥ 60 | 可用 |
| 过曝/糊成一片白 | > 200 | < 40 | 典型"堆白化词"的产物 |
| 过暗/糊成黑块 | < 80 | 低 | 负向里 `dark` 类词过量 |
| 发灰 | 正常 | < 50 | 光线词互相打架（两个光源同时出现） |

## 怎么用

```bash
pip install 'prompt-smith[quality]'
promptsmith gate --image out/01.png -p profiles/example.json
```

或者在自己的脚本里：

```python
from promptsmith.quality import gate
result = gate("out/01.png", profile)
if not result["pass"]:
    print("重出：", result["reasons"])
```

## 阈值的意义

档案里的 `quality_gate`：

```json
{ "brightness": [110, 175], "contrast_min": 60 }
```

这个区间不是什么标准答案，而是**你自己风格的正常范围**。定法：

1. 挑 5~10 张你**满意**的旧图
2. 跑一遍 `measure()`，看亮度和对比度的分布
3. 用分布的中间 80% 作为区间

换 LoRA、换 checkpoint、换画风，阈值都该重新标定一次。

## 它的边界（很重要）

量化质量门只能拦"明显跑偏"，**不能判断好不好看**：

- ✅ 能发现：过曝、发灰、光源打架
- ❌ 不能发现：构图歪、手指崩、表情不对、内容不符

所以正确的用法是**两层**：

```
第一层：数字门（自动，快速，拦掉明显废稿）
第二层：人眼/视觉模型（判断"这张是不是我要的"）
```

把数字门当"初筛"，不要当"验收"。
